# OpenFatture 2.4.0

This release makes the terminal assistant and direct invoicing commands reliable
across independent CLI processes, with explicit outcomes and safer tool execution.

## Highlights

- Markdown chat previews, localized help, input history, slash completion and
  clean normal output. Use `openfatture --debug assistant` for diagnostics.
- `openfatture init` starts setup directly; `fattura list` and `cliente list`
  initialize their database connection without a prior assistant process.
- Setup saves the user TOML profile. Explicit values, environment variables and
  the current `.env` override it. Existing database URLs remain supported.
- Missing or invalid fiscal fields are listed by `status`; RF19 is not assumed.
  Assistant readiness describes configuration, not remote authentication.
- DeepSeek and other OpenAI-compatible endpoints honor `AI_BASE_URL`.
- Partial turns keep known token usage, status and tool outcomes. Unknown prices
  are identified rather than using a fallback OpenAI tariff.

## Tool execution and compatibility

The upstream fail-closed transmit policy is preserved. SDI/PEC tools remain off
unless explicitly named in `ai_enabled_tools`; `all` does not enable them.
Confirmation follows `ai_tools_require_confirmation` (default true). Model
parameters cannot grant approval. The terminal UI supplies a human approval
callback; scripts receive a structured refusal when approval is unavailable.
The obsolete `confirm=False` argument is accepted for compatibility and never
grants approval.

Tools now execute once by default. Only operations explicitly declared safe to
repeat may retry connection errors or timeouts. Approval refusals and cache hits
do not retain concurrency slots. Credentials are masked in nested diagnostic
payloads, configuration output and terminal approval summaries.

## Updating

Install the `ai` extra to use the assistant. Core invoicing does not require the
optional RAG or ML stacks. Existing installations should keep their configured
absolute database URL and review `openfatture status` after upgrading.

PDF copies downloaded separately are not automatically imported into the database.
No invoice transmission or fiscal-data migration is performed by this upgrade.
